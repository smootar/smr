# Scenic Mountain Roofing

Marketing site for Scenic Mountain Roofing — residential and commercial roofing across Utah.

A single-page static site: no build step, no dependencies, no framework. What is committed is
what ships.

## Local development

```bash
python3 -m http.server 8000    # then open http://localhost:8000
lsof -ti:8000 | xargs kill     # stop the server
```

## Structure

```
index.html              Entire site (all sections, JSON-LD, contact form)
css/normalize.css       Vendor reset
css/main.css            Design system + all component styles
css/responsive.css      Breakpoint overrides only (1150 / 1024 / 860 / 780 / 640 / 560 / 420)
js/main.js              Nav, scroll-spy, FAQ, reveals, action bar, form validation
js/color-studio.js      Swatch selection, summary, hand-off into the form
images/logo/            Logo variants, mountain mark, favicons
images/og-image.png     1200x630 social share card
```

## Logo assets

All variants are generated from `images/logo/smr-logo-source.png` (the original black-on-white
artwork). Regenerate them with the scripts noted in `CLAUDE.md` if the source art changes.

| File | Use |
| --- | --- |
| `smr-logo.png` / `.webp` | Dark logo, transparent background — light sections |
| `smr-logo-white.png` / `.webp` | White logo — dark sections and the hero |
| `smr-logo-sm` / `smr-logo-white-sm` | 480px wide, for the header and footer |
| `mark-512.png` / `mark-white-512.png` | Mountain mark only, square; `mark-512` is the favicon source |
| `favicon.ico`, `favicon-16/32/180.png` | Browser and Apple touch icons |

## Photographs

Photos live in `images/roofs/` and are generated by `tools/build-photo-assets.py` from any
`*-source.png|jpg` in that directory. Photos get **WebP + JPEG** (not PNG, which roughly triples
the bytes on photographic content), and are never upscaled — the ladder is capped by whatever
resolution the original actually has, plus the source's own native width.

| File | Use |
| --- | --- |
| `dynasty-home-source.png` | Original artwork — the input, not served |
| `dynasty-home-{480,640,747}.webp/.jpg` | The IKO Dynasty panel in the Materials section |

Drop a new `*-source.*` file in and re-run the script to add a photo.

## Contact form

Posts to [FormSubmit](https://formsubmit.co/) at `tayton@scenicmtnroofing.com`. The address must be
activated once — submit the form a single time and click the confirmation link FormSubmit emails.
The `_next` redirect points at the production domain, so end-to-end submission cannot be tested
from `localhost`.

## Deploying

GitHub Pages serves this repo from the root of `main`. Push and it goes live in one to two minutes.

The production domain is **scenicmtnroofing.com**. DNS is currently at Squarespace and still
points at Squarespace's servers, so the site is served from the `github.io` URL until those records
are changed. Email for the domain is on Google Workspace — its `MX` and SPF records live in the
same zone and must be left intact; adding the GitHub Pages records below does not affect mail.

There is deliberately **no `CNAME` file** in the repo: GitHub Pages reads it and immediately claims
the custom domain, which would make the site unreachable while DNS still points elsewhere. Add it
as the last step, once the records below have propagated:

```bash
echo "scenicmtnroofing.com" > CNAME && git add CNAME && git commit -m "Point Pages at scenicmtnroofing.com" && git push
```

At the DNS host, for the apex:

```
A     @   185.199.108.153
A     @   185.199.109.153
A     @   185.199.110.153
A     @   185.199.111.153
CNAME www smootar.github.io.
```

Then in the repo's Settings → Pages, set the custom domain to `scenicmtnroofing.com` and enable
"Enforce HTTPS" once the certificate is issued (this can take up to 24 hours).

Verify propagation with `dig scenicmtnroofing.com +short`.

The domain appears in `CNAME`, `sitemap.xml`, `robots.txt`, and in `index.html`'s canonical tag,
OG/Twitter URLs, JSON-LD and the form's `_next` redirect — change it in all of them together.
